# 2.5D立ち絵システム仕様書 v0.1

## 1. 目的

Three.js上で、1枚絵から生成した2Dパーツを組み合わせて立ち絵を構築する。

Live2Dのような高密度メッシュ変形は行わず、

- パーツ階層
- 簡易ボーン
- パーツ回転
- テクスチャ差し替え
- 微小な位置・スケール変形

によって、低コストで表情・ポーズ・常時アニメーションを実現する。

主用途はADV・会話画面用キャラクター立ち絵とする。

---

## 2. 基本方式

キャラクターは以下の3要素から構成する。

### Expression

顔パーツのテクスチャ差し替え。

対象：

- 目
- 眉
- 口
- 頬
- 涙
- 汗
- その他表情エフェクト

### Pose

身体ボーンの回転・位置変更と手Spriteの差し替え。

対象：

- 胴体
- 上腕
- 前腕
- 手

### Motion

常時または一時的なアニメーション。

例：

- 呼吸
- 瞬き
- 身体揺れ
- 髪揺れ
- 驚き
- 頷き
- 首振り

Expression / Pose / Motion は互いに独立して適用できるものとする。

---

## 3. Three.js構造

```text
CharacterRoot
│
├─ BodyRoot
│   ├─ Torso
│   │
│   ├─ Neck
│   │   └─ HeadRoot
│   │       ├─ BackHair
│   │       ├─ FaceBase
│   │       ├─ Eye_L
│   │       ├─ Eye_R
│   │       ├─ Eyebrow_L
│   │       ├─ Eyebrow_R
│   │       ├─ Mouth
│   │       ├─ FaceOverlay
│   │       ├─ FrontHair
│   │       └─ Accessories
│   │
│   ├─ UpperArm_L
│   │   └─ ForeArm_L
│   │       └─ Hand_L
│   │
│   └─ UpperArm_R
│       └─ ForeArm_R
│           └─ Hand_R
```

基本実装：

- ボーン：`THREE.Group`
- パーツ：`THREE.Mesh + PlaneGeometry`
- テクスチャ：透過PNG/WebP
- 階層変形：Three.js Object3D Transform
- 描画順：`renderOrder`

SpriteではなくPlaneGeometryを標準とする。

理由は将来的に、

- 頂点変形
- シェーダ変形
- マスク
- クリッピング
- UVアニメーション

へ拡張しやすいため。

---

## 3.1 GLB化方針

Character PackからThree.js Runtimeで扱えるGLBを生成する。

GLBには主に以下を保持する。

- ノード階層
- Transform
- PlaneGeometry
- Material
- Texture
- 基本Animation
- パーツ識別用userData

Expression / Pose / Character Pack固有情報は、必要に応じて外部JSONと併用する。

標準出力：

```text
character.glb
character.json
character.glb.meta.json
```

`character.glb` は表示・ボーン・テクスチャの実体、`character.json` はCharacter Packの実行定義、`character.glb.meta.json` はGLB補助メタデータとする。

## 9. 座標系

元イラストをキャラクター座標系の基準とする。

```text
source_width  = 2048
source_height = 3072
```

各パーツは元画像上での位置情報を必ず保持する。

```json
{
  "source_rect": {
    "x": 281,
    "y": 612,
    "width": 204,
    "height": 351
  }
}
```

パーツPNG生成後もこの座標を失わない。

### 必須条件

初期状態の全パーツを配置すると、元イラストとほぼ同一の画像へ復元できること。

これをキャラクターデータ生成の品質基準とする。

---

## 10. Pivot

回転パーツは必ずPivotを持つ。

```json
{
  "pivot": {
    "x": 102,
    "y": 24
  }
}
```

Pivot座標はパーツローカル座標。

代表例：

```text
upper_arm → shoulder
forearm   → elbow
hand      → wrist
head      → neck
```

## 11. 常時アニメーション

### Blink

```text
normal
↓
half
↓
closed
↓
half
↓
normal
```

ランダム間隔で実行する。

### Breathing

微小な、

```text
torso.scaleY
torso.positionY
head.positionY
```

変化。

### Body Sway

CharacterRootまたはBodyRootを微小回転。

### Hair Sway

前髪・後ろ髪を約1〜2度程度回転。

## 14. パーツ生成の重要条件

単純な切り抜きではなく、**Occlusion Completion** を行う。

元画像上で他パーツに隠れている領域について、可動に必要な範囲まで補完する。

対象例：

- 前髪に隠れた額や顔輪郭
- 胴体に隠れた上腕
- 髪に隠れた肩
- 袖や胴体に隠れた前腕

補完範囲は必要最小限とする。

画像切り取り・補完工程は、完成済みCharacter Packとは別の製造工程データとして保持する。

```json
{
  "schema_version": "0.1",
  "source": {
    "image": "source/original.png",
    "width": 2048,
    "height": 3072
  },
  "character_region": {
    "bbox": {
      "x": 312,
      "y": 104,
      "width": 1430,
      "height": 2860
    },
    "confidence": 0.99
  },
  "parts": [
    {
      "id": "face_base",
      "category": "face",
      "side": "center",

      "source_region": {
        "bbox": {
          "x": 720,
          "y": 310,
          "width": 620,
          "height": 690
        }
      },

      "segmentation": {
        "mask": "work/masks/face_base.png",
        "confidence": 0.96
      },

      "occlusion": {
        "required": true,
        "occluded_by": [
          "hair_front"
        ],
        "completion_mask": "work/completion_masks/face_base.png"
      },

      "output": {
        "image": "parts/face/face_base.png",
        "width": 620,
        "height": 690
      },

      "transform": {
        "anchor": {
          "x": 720,
          "y": 310
        },
        "pivot": {
          "x": 310,
          "y": 650
        },
        "rotation": 0,
        "scale": 1
      },

      "render_order": 500,
      "status": "approved",

      "validation": {
        "alignment_error_px": 0.8,
        "confidence": 0.98
      }
    }
  ],

  "reconstruction": {
    "output": "debug/reconstructed.png",
    "comparison": "debug/reconstruction_diff.png",

    "metrics": {
      "mean_pixel_error": 0.021,

    },

    "status": "pass"
  },

  "review": {
    "requires_manual_review": false,
    "warnings": []

}
```

中間スキーマでは以下を別概念として保持する。

```text

segmentation
occlusion
output

```

これにより、

- 元画像に存在していた領域
- AIが検出した領域
- 隠れていて生成した領域
- 最終出力画像
- Runtime上の配置
- 品質検証結果

を分離して管理する。

## 18.6 ViewerとRuntimeの関係

Viewerは最終Runtimeとは分離する。

ただし以下の処理は共有する。

- GLB Loader
- Character JSON Loader
- 座標変換
- Material設定
- Texture差し替え
- Expression適用
- Pose適用
- Motion適用
- Layer制御

ViewerをRuntimeの最小リファレンス実装として扱い、Viewerで正常に動くCharacter PackはRuntimeでも同じ挙動になることを目標とする。

# 24. Character Pack承認条件

以下をすべて満たした場合に `approved` とする。

- 必須パーツが揃っている
- 初期配置で元絵を再構築できる
- 差分が許容範囲内である
- Pivot位置が自然である
- Layer順に破綻がない
- 必須表情が正常に表示できる
- 必須ポーズが正常に表示できる
- Expression + Poseの組み合わせに破綻がない
- Motion適用時に破綻がない
- GLB Viewerで階層、Pivot、Bone、Alpha、Texture、Layerを確認できる
- Three.js RuntimeでGLBとCharacter JSONを正常に読み込める
- 人間による最終承認が完了している

# 27. 統合アニメーションタイムライン追加仕様

Expression、Pose、Motion、Sprite差分、Morph Target、Bone Animation、Procedural Animationを、1つの `AnimationDocument` として扱う。

```text
AnimationDocument
├─ clip tracks
├─ bone / node tracks
├─ morph tracks
├─ sprite tracks
├─ behavior tracks
└─ event callbacks
```

例：

```json
{
  "version": 1,
  "id": "anes_demo",
  "duration": 5.0,
  "loop": true,
  "tracks": [
    {
      "type": "clip",
```
