# 2.5D Acting Character System — 実装設計 v0.1

## 0. 文書状態

- 状態：実装着手用ドラフト
- 対象：既存PNE頭部View StateへBody Acting Assetを接続する
- 参照：`2.5D Acting Character System — 体験設計.md`
- 既存頭部仕様：`PNE 2.5D View State Editor v0.1 — FIX仕様.md`

本書は体験設計を、Blenderオーサリング、GLB/JSON出力、Three.js Runtimeへ落とすための実装境界を定義する。

---

## 1. 結論

頭部と身体は一体の巨大リグにしない。

```text
PNE Head Pack
    ↓ HeadSocketへ装着
Body Acting Asset
    ↓ 小さな反復動作だけを追加
BodyLoop
    ↓
Actor Runtime
```

Body Acting Assetは完成ポーズを正本とする。腕、肩、手首などは、そのBody Assetで必要な場合だけMotion Partとして宣言する。

「任意に腕を動かせる」は、全方向へ無制限に動かせるという意味にはしない。2D素材の継ぎ目と描き込みが破綻しない、小さな可動範囲をBody Assetごとに定義する。大きな身振りや姿勢変更は別Body Acting Assetへ切り替える。

## 2. システム境界

### 2.1 Head Packの責務

- View Stateによるyaw/pitch表現
- DITHERによる隣接View遷移
- 目、眉、口、顎の局所変形
- 表情同期
- 頭部内の遮蔽と描画順
- 頭部Texture Residency
- 頭部の基準アンカー`head_neck_anchor`

既存のPNE View State実装は原則そのまま再利用する。

### 2.2 Body Acting Assetの責務

- 場面固有の完成身体ポーズ
- `head_socket`と首元の接合情報
- 胴、肩、腕、手などの任意Motion Part
- Motion PartのPivot、可動域、重ね代、描画順
- BodyLoopの対応能力
- Body Asset固有のComposite Profile
- 頭部と腕を動かしたときに必要な画面内余白`motion_envelope`

### 2.3 BodyLoopの責務

- 呼吸
- 肩の上下
- 腕の微動
- 手首の小さな動き
- 身体の小さな揺れ
- 頭部Socketの小さな上下、傾き
- 瞬きや視線などHeadチャンネルへ送るイベント

BodyLoopはBody Assetの完成ポーズを壊す絶対ポーズではなく、基本的に加算レイヤーとする。

### 2.4 Actor Runtimeの責務

- Head PackとBody Acting Assetのロード
- `head_neck_anchor`を`head_socket`へ接続
- BodyLoop、Head View、Expression、Cameraの同時評価
- 能力のない任意パーツを安全にスキップ
- Composite Profileと描画順の適用
- Game ModeとMovie Modeで同じ評価結果を返す

## 3. Runtimeノード階層

```text
actor_root
├─ body_asset_root
│  ├─ body_back
│  ├─ torso_base
│  ├─ shoulder_l_socket                 optional
│  │  └─ upper_arm_l                    optional
│  │     └─ elbow_l_socket
│  │        └─ forearm_l                optional
│  │           └─ wrist_l_socket
│  │              └─ hand_l             optional
│  ├─ shoulder_r_socket                 optional
│  │  └─ upper_arm_r                    optional
│  │     └─ elbow_r_socket
│  │        └─ forearm_r                optional
│  │           └─ wrist_r_socket
│  │              └─ hand_r             optional
│  ├─ neck_back
│  ├─ head_socket
│  │  └─ head_pose_root
│  │     └─ pne_head_root
│  ├─ neck_front_mask
│  ├─ neck_shadow
│  └─ body_foreground
└─ actor_effect_root
```

命名は英語ASCIIの`lower_snake_case`を使う。BlenderのMesh Object名とMesh datablock名は一致させる。

`head_pose_root`は小首傾げ、上下動、呼吸追従用である。頭部のyaw/pitch View State切替を、`head_pose_root`の3D回転で代用しない。

## 4. 頭部と身体の接続

### 4.1 必須アンカー

Head Pack：

```text
head_neck_anchor
```

Body Acting Asset：

```text
head_socket
```

接続Transformは次で求める。

```text
head_world_transform
= body_world_transform
× head_socket_transform
× head_pose_transform
× inverse(head_neck_anchor_transform)
```

これにより、頭の原点や画像サイズが異なっても、首の意味アンカーで接続できる。

### 4.2 Head View Policy

Body Assetは、そのポーズで自然に見える頭部View範囲を持つ。

```json
{
  "head_view_policy": {
    "allowed_view_ids": ["front_0", "front_30", "side_30"],
    "yaw_min_deg": -45,
    "yaw_max_deg": 65,
    "pitch_min_deg": -15,
    "pitch_max_deg": 20,
    "fallback_view_id": "front_30"
  }
}
```

Runtime APIへ渡す頭部yaw/pitchはカメラ相対角度とする。Body Assetの向きは`body_facing_yaw_deg`として別に保持する。

### 4.3 首元の継ぎ目

Body側が首と肩を所有する。頭部側は顎、顔、髪を所有する。

首元では次を重ねる。

```text
neck_back
↓
pne_head_root
↓
neck_front_mask / collar / neck_shadow
```

- `neck_back`は頭部の下へ最低限の描き足しを持つ
- `neck_front_mask`は顎下の切断線を隠す
- `neck_shadow`はBody AssetのComposite Profileに従う
- 頭部を左右へ動かしても透明な穴が出ない幅を確保する

長い後ろ髪が肩より後ろへ回るキャラクターは、Head Packに任意の`head_back` Roleを追加し、Body本体より後ろの描画Bandへ置く。既存Head Packで後ろ髪が首より下へ出ない場合は必須ではない。

## 5. 任意の腕可動仕様

### 5.1 Arm Mode

左右の腕は別々に次のModeを持つ。

```text
baked       Body Baseへ描き込み済み。可動しない
segmented   upper_arm / forearm / handを分離し、小さく可動する
absent      画角外、またはポーズ上存在しない
```

片腕だけ`segmented`、反対側は`baked`でもよい。腕組み、頬杖、物を持つ手など、接触関係が強いポーズは原則`baked`とする。

### 5.2 必須Pivot

`segmented`の場合だけ、以下を必須にする。

```text
shoulder_l / shoulder_r
elbow_l / elbow_r
wrist_l / wrist_r
```

手画像をForearmへ直接バインドしない。手は`wrist_*_socket`または`hand_*` Boneへバインドし、手首回転と手差分切替を独立させる。

### 5.3 Joint Seam Padding

可動域は関節の透明余白ではなく、隠れた描き足しを含む重ね代で成立させる。

初期基準：

```text
shoulder overlap : 腕幅の12%以上
elbow overlap    : 腕幅の10%以上
wrist overlap    : 手首幅の12%以上
texture padding  : Runtime解像度で8px以上
```

元絵解像度での実値はJSONへ保存する。Validatorは最終Runtime解像度へ換算して検査する。

### 5.4 Safe Rotation Range

既定値は会話演技用の小さな動きに限定する。

```text
shoulder : -8° ～ +8°
elbow    : -12° ～ +12°
wrist    : -15° ～ +15°
```

値はBody Assetごと、左右ごとに上書きできる。許容範囲を超える命令はRuntimeでclampし、Debug表示へ警告を出す。

20°を超える身振り、腕の前後反転、胴体を横切る動作、物への接触は別Body Assetまたは専用Gesture Assetで表現する。

### 5.5 Motion Envelope

腕や頭を可動域端まで動かしたときに必要な画面余白を、Body AssetのローカルBoundsとして保存する。

```json
{
  "motion_envelope": {
    "min": [-2.65, -0.20, -0.10],
    "max": [2.70, 7.85, 0.15],
    "camera_margin_ratio": 0.06
  }
}
```

Camera Framingは静止時のBody Boundsではなく`motion_envelope`を使う。Validatorは全Jointのmin/neutral/maxをサンプルし、画像切れと継ぎ目を検査する。

## 7. Actor Pack

キャラクター全体はHead Packと複数Body Assetを参照する。

```json
{
  "schema_version": "0.1",
  "id": "anes_actor",
  "head_pack": "head/character.states.json",
  "default_body_asset": "stand_relaxed",
  "body_assets": {
    "stand_relaxed": "body/stand_relaxed/body.asset.json",
    "arms_crossed": "body/arms_crossed/body.asset.json",
    "lean_forward": "body/lean_forward/body.asset.json"
  },
  "body_loops": {
    "idle": "body_loops/idle.animation.json",
    "listening": "body_loops/listening.animation.json",
    "thinking_soft": "body_loops/thinking_soft.animation.json"
  }
}
```

推奨Bundle：

```text

├─ actor.json
├─ head/
│  ├─ character.glb
│  ├─ character.states.json
│  └─ textures/
├─ body/

```

## 8. BodyLoopとTimeline

### 8.1 評価順

```text
1. Body Asset rest pose
2. BodyLoop additive transform
3. Scene/Gesture override
4. HeadSocket pose
5. Head View State
6. Facial Expression
7. Hair / secondary motion
8. Composite Profile
9. Camera
```

### 8.2 Track例

既存Timelineの`bone`、`node`、`clip`、`sprite`、`behavior`を利用できる。BodyLoopには`blend_mode`と`priority`を追加する。

```json
{
  "id": "thinking_soft",
  "duration": 4.0,
  "loop": true,
  "blend_mode": "additive",
  "priority": 10,
  "tracks": [
    {
      "type": "node",
      "target": "head_pose_root",
      "property": "rotation.z",
      "unit": "deg",
      "keys": [
        { "time": 0.0, "value": 0 },
        { "time": 2.0, "value": -3 },
        { "time": 4.0, "value": 0 }
      ]
    },
    {
      "type": "bone",
      "target": "wrist_l_socket",
      "property": "rotation.z",
      "unit": "deg",
      "keys": [
        { "time": 0.0, "value": 0 },
        { "time": 2.3, "value": 5 },
        { "time": 4.0, "value": 0 }
      ]
    }
  ],
  "events": [
    { "time": 1.2, "name": "head.look", "payload": { "yaw_deg": 25 } },
    { "time": 2.7, "name": "face.blink", "payload": { "duration": 0.16 } }
  ]
}
```

任意Nodeが存在しない場合、`optional: true`のTrackはスキップする。必須TrackのTarget不存在はValidation Errorとする。

## 9. 描画順

Actor内ではRoleごとにRender Bandを分ける。

```text
body_back             1000–1099
head_back             1100–1199
body_base             1200–1299
head_face             1300–1399
body_motion_front     1400–1499
head_foreground       1500–1599
actor_effect          1600–1699
```

PNE頭部内の既存`renderOrder`は、対応するHead BandのBase値へ加算する。

```text
actor_render_order = actor_slot_base + role_band_base + local_render_order
```

物理深度と`renderOrder`を併用し、透明Materialは原則`depthWrite = false`とする。腕が胴の前後を横切るBody Assetは、パーツ単位でBandを明示する。

## 10. Composite Profile

Head SystemをBody Assetへ馴染ませる補正は、HeadのSource Textureを破壊せずShader Uniformで適用する。

最低限：

```text
exposure
temperature
saturation
shadow_tint
highlight_tint
neck_shadow_opacity
```

同じProfileをHeadのView A/Bへ同時適用し、DITHER遷移中に色が変わらないようにする。Body Asset切替時のProfile遷移は0.1〜0.3秒の補間を許可する。

## 11. Runtime API

```ts
interface ActingCharacterController {
  setBodyAsset(id: string, transition?: 'cut' | 'dither'): Promise<void>;
  setBodyLoop(id: string | null, fadeSeconds?: number): void;
  setHeadView(yawDeg: number, pitchDeg: number): void;
  setLook(x: number, y: number): void;
  setExpression(channels: Record<string, number>): void;
  setArmPose(side: 'left' | 'right', pose: ArmPose): void;
  setCompositeProfile(profile: CompositeProfile, fadeSeconds?: number): void;
  update(deltaSeconds: number): void;
  seek(timeSeconds: number): void;
}
```

`setArmPose`はBody Assetが`segmented`を宣言している側だけに効く。`baked`または`absent`へ呼んだ場合は無視し、Debug時のみ警告する。

Body Asset切替のv0.1標準は`cut`とする。切替カットを跨いで同一Headを維持し、HeadSocketだけを新Bodyへ付け替える。Body同士のDITHERは後から追加できる。

## 12. Blenderオーサリング

### 12.1 Body Asset作成手順

1. 完成ポーズ画像を背景、胴、首元、必要な腕パーツへ分ける
2. 隠れる関節部分を描き足す
3. `head_socket`を置く
4. 可動腕だけ肩、肘、手首Socketを置く
5. Planeを各Socketへ剛体バインドする
6. Safe Rotation Rangeのmin/neutral/maxを確認する
7. `motion_envelope`を計算する
8. Composite Profileを設定する
9. Validatorを通す
10. `body.glb + body.asset.json + textures`を出力する

### 12.2 保存原則

- 既存Head PackをBody AssetへJoinしない
- HeadのMesh、Shape Key、MaterialをBody作成時に変更しない
- Source画像を上書きしない
- 可動腕を持たないBodyへダミーBoneを強制しない
- 全可視MeshはObject名とMesh datablock名を一致させる

## 13. Validator

### 13.1 必須検査

```text
Body Asset ID重複
body.glb不存在
head_socket不存在
head_neck_anchor不存在
Head View Policy不正
Render Band不足
Composite Profile範囲不正
Motion Envelope不足
Runtime Texture不存在
Object名とMesh datablock名の不一致
```

### 13.2 segmented腕だけに行う検査

```text
肩・肘・手首Socket不存在
upper_arm / forearm / hand不存在
手のForearm直結
min_deg >= max_deg
Safe Range外のBodyLoop Key
関節Overlap不足
min/neutral/maxで透明な穴
腕のMotion Envelope外突出
胴との描画順破綻
```

### 13.3 Visual Validation

各Body Assetについて次のContact Sheetを出力する。

```text
head view : front_0 / front_30 / side_30
head roll : min / neutral / max
arm       : min / neutral / max
loop      : 0% / 25% / 50% / 75%
```

頭部の浮き、首の切断線、腕の隙間、袖の破綻、画面切れ、前後順を目視確認する。

## 14. 現行リポジトリからの実装差分

現行コードには再利用できる要素がある。

- PNE Headは4 View、DITHER、Expression同期、Texture Residencyを既に分離している
- ANES試作は`CharacterRoot / BodyRoot / HeadRoot / UpperArm / Forearm / Hand`の意味階層を持つ
- Timelineは`clip / bone / node / morph / sprite / behavior`を評価できる
- ANES試作は剛体腕パーツと小さなIdle腕モーションを既に検証している

不足している実装境界：

```text
1. PNE Head Packへhead_neck_anchorを追加
2. Body Asset用body.asset.json Schemaを追加
3. head_socketへの装着Runtimeを追加
4. Optional Arm CapabilityとSafe Range clampを追加
5. handをwrist/hand Socketへ独立バインド
6. Composite Profile Shaderを追加
7. Render Band統合を追加
8. Motion Envelope Validatorを追加
9. Timelineへadditive/priority/optionalを追加
```

推奨コード配置：

```text
viewer/app/acting-character-runtime.ts
viewer/app/body-acting-runtime.ts
viewer/app/acting-character-schema.ts
blender_addon/pne_2_5d/body_assets.py
blender_addon/pne_2_5d/body_validator.py
blender_addon/pne_2_5d/body_exporter.py
```

既存`pne-view-state-runtime.ts`と`animation-timeline.ts`は置き換えず、上位のActor Runtimeから利用する。

## 15. 実装順

```text
01 Head Packへhead_neck_anchor追加
↓
02 1枚Body + head_socketで接続
↓
03 首元mask / shadow / Render Band
↓
04 片腕だけsegmented化
↓
05 Safe Range clamp + Motion Envelope
↓
06 Idle BodyLoop
↓
07 Thinking BodyLoopからHead/Expression Event発火
↓
08 Composite Profile
↓
09 2つ目のBody Assetへcut切替
↓
10 Game Mode / Movie Mode共通再生
```

最初のGo/No-Go地点は03である。

```text
Head Viewをfront_0 → front_30 → side_30へ動かし、
小首傾げを±4°行っても、
首元が浮かず、切れず、色が馴染むこと。
```

次のGo/No-Go地点は05である。

```text
腕をSafe Rangeのmin/neutral/maxへ動かしても、
関節に透明な穴がなく、袖の形が破綻せず、
Camera Safe Frameから出ないこと。
```

## 16. v0.1完成条件

1. 既存PNE Headを再ExportせずBodyへ装着できる
2. 1つのHead Packを2つ以上のBody Assetで共有できる
3. Head View遷移中もBodyLoopが継続する
4. BodyLoop中もBlink、視線、口パクが独立して動く
5. `baked / segmented / absent`の腕が同一Runtimeで扱える
6. segmented腕がSafe Range外へ出ない
7. 首元と腕の継ぎ目に透明な穴が出ない
8. `motion_envelope`内でCamera Frameが決まる
9. Composite ProfileがHead View A/Bへ同期する
10. Body Asset切替後もHead Expression状態を維持する
11. Game ModeとMovie Modeの同一時刻で同一姿勢になる
12. Blender ValidatorとRuntime Validatorが同じSchemaを検査する

## 17. v0.1の対象外

- 腕の無制限なIK
- 360°の身体回転
- 激しい全身アクション
- Body Asset間の連続Mesh Morph
- 手と小物の自動接触解決
- 多人数の身体接触

これらが必要な演技は、別Body Acting Assetまたは専用カットとして制作する。
