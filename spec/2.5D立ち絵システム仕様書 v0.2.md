# 2.5D立ち絵システム仕様書 v0.2

## 0. 文書状態

- 状態：実装前の確定方針
- 作成日：2026-08-29
- v0.1との関係：本書で定義した内容を優先する。v0.1と矛盾する箇所は本書で上書きする。

本システムは、1枚絵から生成・分解した2Dパーツを、Three.js上で組み合わせて表示・アニメーションする量産向け2.5D立ち絵システムである。

目的は、固定表情を切り替えるだけの表示ではなく、目パチ、口パク、眉、髪揺れ、身体モーション、推論による表情制御を、動画編集ソフトのようなタイムラインで編集し、同じデータを実行時に再生できる状態にすることである。

---

## 1. 基本方針

### 1.1 2.5Dカットアウト方式

Live2Dのような高密度な全身変形を必須としない。以下の方式を組み合わせる。

- パーツ分離
- PlaneGeometry
- Transform（位置、回転、スケール）
- 少数ボーン
- テクスチャ／アトラス領域の切り替え
- Shape Key / Morph Target
- シェーダーによる補助変形
- 簡易Springによる物理揺れ

### 1.2 論理ノードと画像アセットを分離する

アニメーションは画像ファイル名やピクセル座標を直接参照しない。

```text
Animation JSON
  ↓ semantic target
Character Node
  ↓ asset reference / atlas rect
Atlas or GLB
```

同じアニメーションを、女性モデル、8頭身男性モデル、眼鏡あり／なしのキャラクターへ適用できることを目標とする。

### 1.3 JSONを正本とする

GSAPやThree.jsのオブジェクトを保存形式にしない。保存するのは独自のシリアライズ可能なJSONである。

```text
Animation JSON
  ↓
Timeline Evaluator
  ├─ GSAP adapter（エディタ・再生補助）
  ├─ Three.js Transform
  ├─ Texture / Atlas UV切り替え
  ├─ Morph Target
  └─ Physics / Procedural layer
```

EditorとRuntimeは同じEvaluatorを使用し、エディタで見える結果とゲーム内の結果を一致させる。

## 2. システム構成

```text
Source Illustration
        ↓
Generation / Segmentation
        ↓
Part Cleanup / Hidden Completion
        ↓
Individual Source Parts
        ↓
Atlas Packer
        ↓
character.glb + character.json + atlas.png + atlas.json
        ↓
Editor / Runtime
```

### 2.1 出力ファイル

```text
character.glb
  ノード階層、Plane、ボーン、Morph Target、基本Animation

character.json
  Character Pack、論理パーツ、アンカー、バインディング、能力情報

atlas.png
  実行時に使用するテクスチャアトラス

atlas.json
  アトラス領域、元画像サイズ、トリミング、Padding、Pivot情報

animation.json
  タイムライン、ノード、キーフレーム、イージング、イベント
```

## 3. 生成・分解工程

### 3.1 生成用の基準画像

量産時はキャラクターごとに、次の基準画像を生成する。

```text
front_fullbody.png  正面・直立・全身
face_closeup.png    顔パーツ分解用の高解像度画像
```

必要に応じて以下を追加する。

```text
hair_reference.png
accessory_reference.png
back_hair_reference.png
```

生成条件は以下を基本とする。

- 正面
- 直立または軽い自然立ち
- 透視歪みを抑える
- 手を身体に重ねない
- 顔の各要素を明瞭にする
- 髪を前髪・横髪・後ろ髪として識別しやすくする
- 眼鏡、髪、顔、衣服の境界を明確にする
- 背景、影、文字、ロゴを含めない

### 3.2 SAM系ノードによる分解

ComfyUIのSAM/SAM2系ノードを使って大分類を自動化する。

```text
Generation
  ↓
GroundingDINO等による対象指定（必要時）
  ↓
SAM / SAM2 mask
  ↓
Mask cleanup
  ↓
Hidden area completion
  ↓
Semantic naming
```

SAMは髪、顔、眼鏡、胴体、腕、手、脚などの大きな領域に使う。目、眉、口、ハイライトのような細部は、顔アップ画像、点指定、手動修正、または専用生成を併用する。

### 3.3 編集用素材と実行用素材

編集用の個別画像は分離状態で保持する。

```text
face_new/
├─ face_base.png
├─ eye_l_sclera.png
├─ eye_r_core.png
├─ brow_r.png
├─ mouth/
└─ face_effect/
```

これらをビルド時に自動パックし、実行時はアトラスを使用する。アトラス画像を手作業で直接編集しない。

## 5. 顔パーツ仕様

### 5.1 目

左右のノードは分ける。ただし、左右で同じ画像を使う場合は同じアトラス領域を参照し、片側を`flipX`で反転してよい。

```text
eye_l
├─ eye_l_sclera          白目
├─ eye_l_core            虹彩・瞳孔など。ハイライトを除く
├─ eye_l_highlight       キャッチライト
├─ eye_l_lid_upper_line  上まぶた線・まつ毛
├─ eye_l_lid_upper_fill  肌色の遮蔽領域
└─ eye_l_lid_lower_line  下まぶた線

eye_r
├─ eye_r_sclera
├─ eye_r_core
├─ eye_r_highlight
├─ eye_r_lid_upper_line
├─ eye_r_lid_upper_fill
└─ eye_r_lid_lower_line
```

前後順は概ね以下とする。

```text
lid_upper_line
lid_lower_line
lid_upper_fill
highlight
core
sclera
face_base
```

`lid_upper_fill`は、上まぶた線の内部が透明で、後ろの白目・眼球が見えてしまう場合に必要となる。線と塗りを1枚に統合してもよいが、閉眼時に目を隠す不透明領域は必要である。

### 5.2 目のボーンとShape Key

眼球を動かすボーンと、まぶたを変形するShape Keyの役割を分ける。

```text
EyeBall_L bone
  ├─ eye_l_sclera
  ├─ eye_l_core
  └─ eye_l_highlight

EyeSocket_L / HeadRoot
  ├─ eye_l_lid_upper_line  Shape Key
  ├─ eye_l_lid_upper_fill  Shape Key
  └─ eye_l_lid_lower_line  Shape Key（必要時）
```

白目、虹彩、瞳孔を個別に閉眼変形させる方式は、各パーツの同期と形状維持が難しくなるため標準にしない。

### 5.3 瞬き

左右別のチャンネルを持つ。

```text
blink_l: 0.0 開眼 → 1.0 閉眼
blink_r: 0.0 開眼 → 1.0 閉眼
```

同じチャンネルから、上まぶた線、肌色Fill、ハイライトの透明度を制御する。ハイライトは必要に応じて瞬き中に非表示または減衰させる。

### 5.4 眉

眉本体は左右別ノードにする。画像アセットは左右で共有・反転してよい。

```text
brow_l
brow_r
brow_glabella_crease
```

眉間のしわは共通の中央オーバーレイとする。眉本体に含めず、`anger`または`tension`パラメータから透明度・Shape Keyを制御する。

```text
anger = 0.0  → crease opacity 0
anger = 1.0  → crease opacity 1
```

しわの表示のために、通常時だけZ位置を変更する設計にはしない。しわは常に顔より手前へ配置し、非表示または透明度0で待機させる。

### 5.5 口

口は共通ノードとする。

```text
mouth
```

口形状はアトラス内のテクスチャ切り替えを基本とする。

```text
mouth_normal
mouth_smile
mouth_sad
mouth_open
mouth_shock
```

口パクで滑らかな開閉量が必要な場合は、口テクスチャ切り替えと`mouth_open`のTransform、透明度、またはMorph Weightを組み合わせる。

## 6. 髪パーツ・ボーン・物理

### 6.1 髪の命名

単なる横髪よりも、長い髪束は`side_lock`として表現する。

```text
hair_back
hair_front
hair_side_lock_l
hair_side_lock_r
```

階層を持たせる場合は、以下のようにする。

```text
hair_side_l
└─ hair_side_lock_l

hair_side_r
└─ hair_side_lock_r
```

ボーンは2〜3段を標準とする。

```text
hair_side_lock_l_root
hair_side_lock_l_mid
hair_side_lock_l_tip
```

左右で画像が同一なら、画像は共有し、片側を反転する。ノードとボーンは左右別にする。

### 6.2 髪の変形方式

髪が単一の四角形Planeの場合、複数ボーンを追加しても曲がらない。次のいずれかを使う。

- 髪を2〜3枚のカードへ分割し、各カードを剛体バインド
- 髪Planeを縦方向に分割し、ボーンウェイトで変形
- 分割Planeへシェーダー変形を加える

初期実装は、少数ボーン＋分割カードを優先する。軽量で、2.5Dらしい見た目を維持しやすいためである。

### 6.3 髪物理

Three.jsで髪専用の軽量Spring/Verlet処理を実装する。外部の大規模物理エンジンは必須としない。

```text
Base Animation
      +
Procedural Sway
      +
Physics Overlay
      ↓
Hair bones
```

物理パラメータ例：

```json
{
  "stiffness": 0.72,
  "damping": 0.18,
  "gravity": 0.05,
  "wind": 0.02,
  "max_angle": 8
}
```

物理は再生中に使用できるが、タイムラインのシーク時に再現性を保つ必要がある。エディタではシミュレーションを初期状態から再生し、書き出し時には必要に応じてBakeしてキーフレーム化する。

## 7. アトラス仕様

### 7.1 基本方針

編集用の個別PNGを、生成・ビルド段階で自動パックする。左右の同一素材を画像として複製しない。

```text
source part image → atlas rect
logical node      → asset ID + flipX
```

顔アトラスはキャラクターごとに持ってよい。全キャラクターの画像を1枚へ統合することは必須としない。

### 7.2 パッキング条件

- 透明部分はトリミングする
- 元画像サイズを保存する
- 元画像内のトリミング矩形を保存する
- 3px前後のPaddingを入れる
- Paddingには境界色を押し出す
- 初期版では矩形の回転配置をしない
- UVのY方向反転はBuilder側で処理する
- Pivotはアトラス座標ではなく、元画像基準で保存する

Paddingなしの完全な隙間詰めは、縮小時の隣接画像のにじみを起こすため禁止する。

### 7.3 アトラスメタデータ

```json
{
  "schema_version": "2.0",
  "atlas": {
    "image": "atlas.png",
    "width": 1024,
    "height": 512,
    "padding": 3,
    "extrude": true,
    "trim": true,
    "square": false
  },
  "sprites": {
    "brow_r": {
      "x": 120,
      "y": 80,
      "width": 74,
      "height": 39,
      "source_size": [74, 39],
      "source_rect": [0, 0, 74, 39],
      "trimmed": false,
      "source_path": "brow_r.PNG"
    }
  }
}
```

### 7.4 現在の自動生成結果

現在の顔素材から、以下の自動生成スクリプトと初版アトラスを作成済みである。

```text
tools/pack_face_atlas.py
asset/anes_check/anes/F_face/face_new/atlas.png
asset/anes_check/anes/F_face/face_new/atlas.json
```

現時点では21素材を`1024×512`へ配置している。これはアトラス生成の検証用であり、GLBの各Plane UVへ接続する工程は別途実装する。

## 8. タイムライン・エディタ仕様

### 8.1 動画編集ソフト型UI

メインタイムラインには、複雑な表情や演出を1つのクリップとして置く。

```text
Main Timeline
────────────────────────────────
Idle        ─────────────────────
Blink              [Blink]
Surprise                    [Surprise]
Talk        [Mouth Talk────────]
────────────────────────────────
```

クリップは以下を持つ。

- 開始時刻
- 終了時刻
- 長さ
- 入出力ハンドル
- ループ設定
- ブレンド設定
- 有効／無効
- ネストされた内部タイムライン

### 8.2 Compound Clip

`Surprise`や`Blink`のような演出は、メインタイムラインでは1ノードとして扱う。ダブルクリックすると内部タイムラインを編集できる。

```text
Surprise / Nested Timeline
────────────────────────────
brow_l       ──╱╲──────────
brow_r       ──╱╲──────────
eye_l        ─╱  ╲─────────
eye_r        ─╱  ╲─────────
mouth        ──╲  ╱────────
head         ──╱╲──────────
crease       ───fade───────
────────────────────────────
```

Compound Clipは再利用可能なAnimation Assetとする。キャラクター固有のノードへバインドするため、直接Mesh名を固定しない。

### 8.3 ノード種別

最低限、以下を定義する。

```text
SetNode         離散値・テクスチャ・表示切替
TweenNode       数値の補間
SpriteNode      アトラス領域・フレーム切替
MorphNode       Morph Weight / Shape Key
InferenceNode   推論入力から表情チャンネルを出力
PhysicsNode     物理・Procedural制御
CompoundNode    複数ノードをまとめたネストタイムライン
EventNode       音声、SE、イベント、通知
```

### 8.4 イージング

イージングはJSONに名前またはシリアライズ可能なカーブとして保存する。

```json
{
  "ease": "power2.out"
}
```

GSAPはこのイージングを再生へ変換するアダプターとして使用できる。GSAPの関数自体をJSONへ保存しない。

### 8.5 MorphTargetInference

推論ノードは、毎フレームのブラックボックス処理ではなく、表情チャンネルを出力する制御ノードとする。

```text
Voice / Emotion / Event
        ↓
MorphTargetInference
        ↓
blink_l / mouth_open / brow_l_raise / anger
        ↓
Timeline bindings
```

出力例：

```json
{
  "type": "inference",
  "model": "MorphTargetInference",
  "input": "voice",
  "outputs": {
    "mouth_open": "face.mouth.open",
    "eye_open_l": "face.eye_l.open",
    "eye_open_r": "face.eye_r.open"
  }
}
```

推論結果は、必要に応じてキーフレームまたはカーブへBakeし、同じJSONを再現できるようにする。

## 10. 量産用Character Pack

### 10.1 キャラクター固有情報

キャラクターごとに以下を定義する。

- パーツ画像・アトラス
- ノード階層
- アンカー位置
- Pivot
- ボーン一覧
- Morph Target一覧
- 使用可能な表情・ポーズ・物理
- オプションパーツ
- 左右反転情報

### 10.2 アンカー

固定ピクセル座標ではなく、意味のあるアンカーでパーツを配置する。

```text
head_center
neck
eye_socket_l
eye_socket_r
mouth_center
shoulder_l
shoulder_r
hand_l
hand_r
foot_l
foot_r
```

8頭身男性モデルでは、頭身、肩幅、脚長、顔位置などが変わるため、アンカーとパーツごとのローカル座標から再配置する。

### 10.3 オプションパーツ

モデルによって存在しないパーツを許容する。

```text
beard
mustache
glasses
earring
hair_side_lock
face_shadow
tear
```

存在しないターゲットを含むアニメーションは、無視またはフォールバックする。キャラクターごとのコード分岐を増やさない。

### 10.4 8頭身眼鏡男性での検証

量産仕様を確定する前に、少なくとも以下の2体で同じAnimation JSONを再生する。

```text
ANES女性モデル
8頭身眼鏡男性モデル
```

以下がコード変更なしに動作することを合格条件とする。

- 瞬き
- 口パク
- 左右別の眉
- 眉間のしわ
- 目ボーンによる視線・微移動
- 髪揺れ
- Compound Clip
- イージング

## 11. GLBとRuntimeの責務

### GLB

- ノード階層
- PlaneGeometry
- ボーン
- Morph Target
- マテリアル
- アトラス参照UV
- 基本的な身体Animation

### Character JSON / Animation JSON

- セマンティックID

身体の基本AnimationはThree.js `AnimationMixer`で再生してよい。顔、表情、推論、髪物理はCustom Timeline Layerとして上乗せする。

## 12. 座標・描画順

PlaneGeometryを標準とする。透明パーツを重ねるため、深度軸と`renderOrder`を明示的に管理する。

現在のANESビルドではカメラが-Y方向に置かれているため、奥行きは実装上Y軸を使用している。一般的な説明でZ順と呼ぶ場合でも、実装では既存のY軸規約を優先する。

```text
深度位置 + renderOrder
  ↓
前髪、眼鏡、目線、顔、身体の描画順を決定
```

透明素材の`depthWrite`、`alphaTest`、`DoubleSide`の設定は、重なり順の検証結果に基づいて統一する。

## 13. 実装フェーズ

### Phase 1：素材・アトラス

- 顔パーツの論理命名を確定
- 個別PNGからアトラス生成
- `atlas.json`の読み込み
- 左右共有アセットと`flipX`
- Pivot・Trim検証

### Phase 2：顔Runtime

- `eye_l / eye_r`
